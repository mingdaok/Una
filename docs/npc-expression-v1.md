# NPC 表达层 v1 开发基准

## 目标

NPC 的朋友圈和聊天近况必须来自已经结算、已经持久化的 `ai_actor_events`，不能再次脱离事件账本随机编造生活。

表达层 v1 包含两个出口：

1. 高公开度事件生成 NPC 朋友圈。
2. 高可提及度事件在用户询问具体人物或朋友近况时进入聊天上下文。

## NPC 朋友圈

`LifeSocialWorldService` 在执行前会进行一次幂等 NPC 离线补算，因此定时表达任务可以独立运行，不依赖其他接口先调用生活结算。

事件需要满足：

- 属于当前用户世界中的活跃 NPC。
- 事件时间不晚于当前时间。
- `publicability >= 50`。
- 位于配置的回看时间内。

生成的动态具有以下约束：

- `author_id` 使用稳定 NPC ID。
- `content` 和 `location` 直接来自事件。
- `source_event_ids` 保存唯一来源事件。
- `generation_reason` 为 `npc_autonomous_event`。
- 幂等键为用户和事件 ID 的组合；重复扫描不会重复发帖。
- 每轮最多创建三条，未处理的旧事件会在后续轮次继续处理。
- UNA 可以幂等点赞；v1 不对自主事件自动生成无关评论。

旧版由 UNA 的 `friend_chat` 事件触发的 NPC 社交素材仍保留兼容，但自主 NPC 事件优先处理。

## 聊天上下文

只有以下场景才注入 NPC 近况：

- 用户明确提到当前角色显示名或别名。
- 用户询问“你的朋友”“朋友最近”“他们最近”等朋友近况。

候选事件必须满足：

- 最近七天内发生。
- `mentionability >= 45`。
- `disclosure_level` 不是 `private`。

上下文会包含人物、时间、事件摘要和地点，同时明确提示模型：

- 这是对方自己的生活记录。
- UNA 可以自然转述，但不能说成自己的亲历。
- 不得补充事件中不存在的细节。

普通问候和与 NPC 无关的聊天不会注入 NPC 近况。`private_thought`、内部 `facts` 和状态计算细节不会进入聊天上下文。

## 后续顺序

1. NPC 之间及 NPC 与 UNA 的共同互动事件和多方视角（已完成）。
2. NPC 双向关系状态和证据事件（已完成基础版本）。
3. 用户建议转为 NPC 可接受、延后或拒绝的意向。
4. 关系阈值进一步影响互动概率、内容和冲突修复。
5. NPC 状态、日程、事件和表达来源的调试界面。
