# UNA 本地实时语音通话设计

> 状态：设计已确认，等待文档审阅后编写实施计划
>
> 日期：2026-08-01
>
> 范围：本地桌面浏览器优先，不包含公网部署、群聊和 Live2D 驱动

## 1. 结论

UNA 新增一个独立的“实时语音通话”入口，交互方式接近微信语音通话：用户直接说话，系统自动判断一句话结束，识别后让 UNA 流式思考并用现有 GPT-SoVITS 克隆音色连续回复；用户在 UNA 说话时可以直接插话，前端立即停播旧回复，后端取消旧轮次。

实时语音页不得导入 PixiJS、Live2D 模型、动作编译器、Rhubarb 嘴型或现有模型渲染状态。它与文字聊天共享账号、UNA 人设、对话记录和记忆，但使用独立的前端运行时、独立的 WebSocket 会话和独立的流式音频链路，保证 Live2D 加载、掉帧或动作异常不会影响语音通话。

“本地运行”在本设计中表示：UNA 后端、SenseVoice、GPT-SoVITS、数据库和记忆库均运行在用户电脑上。现有大模型接口可以继续联网调用；完全离线的大模型推理不属于本阶段。

## 2. 目标与非目标

### 2.1 目标

- 用户点击通话按钮后，可持续使用麦克风对话，不需要每句话手动按住或再次点击发送。
- 语音停止后自动结束当前输入，并尽快播放 UNA 的第一段声音。
- 使用现有 GPT-SoVITS 克隆音色，不切换为浏览器或 Edge TTS 作为正常路径。
- 用户插话时，旧回复立即静音，旧文字生成、语音合成和音频分片均停止或失效。
- 实时语音与文字聊天写入同一用户的私有记录和记忆，不建立第二套 UNA。
- Live2D 不加载、不参与、不阻塞实时通话。
- 首版在本机桌面浏览器稳定运行，并为后续局域网手机和 HBuilderX 页面留出协议边界。

### 2.2 非目标

- 本阶段不做公网服务器部署、NAT 穿透、WebRTC TURN、弱网自适应和多机扩容。
- 本阶段不做群聊、多人会议、声纹识别和多说话人分离。
- 本阶段不做 Live2D 嘴型、动作、表情或摄像头画面。
- 本阶段不重写现有文字聊天和 Live2D 页面。
- 本阶段不要求大模型完全离线运行。

## 3. 当前链路的问题

现有 UNA 链路主要为“文本或录音文件 → SenseVoice → 大模型 → 文字切段 → GPT-SoVITS 完整文件 → Rhubarb → 私有媒体 URL → 前端预加载和播放”。它适合带字幕、精确嘴型和可重播音频的 Live2D 页面，但不适合电话式实时对话：

1. 前端语音、文字、Live2D 和动作状态集中在同一 Hook 中，模型运行异常可能影响整页更新与清理。
2. ASR 收到文件后需要启动 FFmpeg 转换，产生额外进程和转码等待。
3. GPT-SoVITS 正常路径等待完整音频文件生成，再执行文件写入、Rhubarb 和媒体票据流程，第一声音更晚。
4. MP3 解码、音频预加载和多分片文件播放会增加句间断粮风险。
5. 现有中断面向页面回复队列，尚未形成“用户开始说话即抢占当前回答”的通话轮次规则。
6. 每轮同步等待较重的记忆检索会直接放大语音响应延迟。

因此实时语音不能只是在现有页面隐藏 Live2D，而应建立一条专用的低延迟链路。

## 4. 参考项目与取舍

### 4.1 采用的思路

- [proj-airi/webai-example-realtime-voice-chat](https://github.com/proj-airi/webai-example-realtime-voice-chat)：采用其浏览器 AudioWorklet、16 kHz 语音活动检测、ASR → 流式 LLM → 分句 TTS → 有序播放的总体流水线思路。
- [ricky0123/vad](https://github.com/ricky0123/vad)：首版使用 `@ricky0123/vad-web` 封装浏览器端 Silero VAD，避免自行维护模型窗口、状态和音频帧拼接。
- [snakers4/silero-vad](https://github.com/snakers4/silero-vad)：使用 Silero VAD 的 16 kHz ONNX 模型作为本地端点检测基础。

### 4.2 只参考、不直接引入

- [Pipecat](https://github.com/pipecat-ai/pipecat)：参考其管线、轮次和中断模型；UNA 首版不引入完整框架，避免与现有 FastAPI、SenseVoice、GPT-SoVITS 和记忆层重复。
- [LiveKit Agents](https://github.com/livekit/agents)：适合后续公网 WebRTC 与弱网场景，本地单用户阶段不引入 LiveKit 服务。
- [TEN Framework](https://github.com/TEN-framework/ten-framework)：参考其可插拔实时多模态设计，当前体量和部署成本超出首版需求。

所有新增依赖在实施前必须核对许可证并锁定版本；浏览器所需 ONNX 与 WASM 资源必须随前端本地发布，运行时不得依赖公共 CDN。

## 5. 总体架构

```text
麦克风
  ↓ AudioWorklet：采集、重采样为 16 kHz/单声道/PCM16
浏览器端 Silero VAD
  ↓ 二进制 PCM + turn_id
专用 WebSocket /ws/voice-call
  ↓
VoiceCallSession（单会话、单活动轮次、可取消）
  ├─ SenseVoice 常驻模型：PCM 直接识别
  ├─ 记忆快照：复用同一用户的 UNA 记忆
  ├─ 大模型：只生成自然回复，不生成 Live2D 控制块
  └─ GPT-SoVITS：raw PCM 流式输出
        ↓ 二进制 PCM + sequence
浏览器 AudioContext：小缓冲、有序连续播放
```

新增语音页使用路由级代码分割。进入该页面时不加载 Live2D 组件、模型资产、PixiJS、动作调度器和 Rhubarb 相关逻辑；返回原聊天页后，原功能保持不变。

## 6. 前端设计

### 6.1 页面与模块边界

新增独立页面及专用模块，职责如下：

- `VoiceCallPage`：通话 UI、状态显示、开始/结束按钮、静音与文本转写展示。
- `VoiceCapture`：麦克风权限、AudioWorklet、重采样、PCM 帧和输入设备生命周期。
- `VoiceActivityDetector`：本地 VAD、预留音频、开始说话和结束说话判断。
- `VoiceCallSocket`：票据换取、协议编解码、断线和会话终止。
- `PcmStreamPlayer`：按轮次与序号缓冲并连续播放服务端 PCM。
- `VoiceCallController`：唯一状态机，协调捕获、识别、生成、播放和插话。

这些模块不引用 `useUnaCore` 的 Live2D 部分。账号令牌刷新和一次性 WebSocket 票据可以复用现有认证客户端，但通话状态不得写入 Live2D 状态。

### 6.2 采集参数

- 浏览器请求回声消除、噪声抑制和自动增益：`echoCancellation`、`noiseSuppression`、`autoGainControl`。
- AudioWorklet 持续采集浏览器原始音频，并在前端转换为 16 kHz、单声道、PCM16 小端序。
- VAD 默认参数：最短有效语音 250 ms、结束静音 400 ms、前置保留 120 ms、单次最长 30 秒。
- VAD 参数集中配置，人工测试后可调整，不散落在组件中。

前置保留用于避免吞掉第一个音节；最大时长用于防止环境噪声造成无限录音。

### 6.3 播放参数

- 服务端在每个语音流开始时声明 `sample_rate`、`channels=1` 和 `format=pcm_s16le`，前端不得假定固定输出采样率。
- 前端先积累约 120 ms 音频再开始播放，随后按 `sequence` 连续调度 AudioBuffer。
- 只允许当前 `turn_id` 的分片进入播放器；旧轮次即使迟到也直接丢弃。
- 播放中保持麦克风和 VAD 工作，用于检测用户插话。
- 前端不保存临时 MP3，不请求媒体 URL，不执行 Rhubarb 嘴型。

### 6.4 UI 状态

主状态机为：

```text
connecting → listening → recognizing → thinking → speaking → listening
                    ↘ error                    ↘ interrupted
任意活动状态 → ended
```

页面显示当前状态、用户最终识别文本和 UNA 的流式回复文字。中间 ASR 假设不作为正式消息写入数据库；只有最终识别结果进入对话记录。

## 7. 专用 WebSocket 协议

### 7.1 连接与身份

沿用现有 Access Token 换取一次性 WebSocket 票据的方式，连接地址为：

```text
/ws/voice-call?ticket=<一次性票据>
```

即使首版仅本机使用，也保留用户身份和数据隔离，避免新增一条绕过认证的旁路。

每次连接创建唯一 `session_id`。VAD 确认用户开始说话时，客户端立即为该次发言创建递增且不可复用的 `turn_id`，随后该次输入、识别、回答和语音都沿用它。同一会话只允许一个活动回答轮次。

### 7.2 控制消息

控制消息使用 JSON，至少包含以下事件：

- 客户端：`call_start`、`user_speech_start`、`user_speech_end`、`interrupt`、`call_end`。
- 服务端：`call_ready`、`transcript_final`、`assistant_text_delta`、`assistant_text_end`、`tts_start`、`tts_end`、`turn_cancelled`、`call_error`、`call_ended`。

与某轮有关的事件必须携带 `session_id` 和 `turn_id`。`tts_start` 还必须包含采样率、声道数和 PCM 格式。

### 7.3 二进制消息

上行二进制帧为用户 PCM16；下行二进制帧为 UNA 的 GPT-SoVITS PCM16。每组二进制分片必须先有一条对应的 JSON 元数据消息，至少声明方向、`turn_id`、该方向内独立递增的 `sequence` 和字节长度。

服务端发送 JSON 元数据与紧随其后的二进制载荷时使用同一个异步发送锁，防止并发任务交错。客户端对长度、轮次、序号和格式做校验，异常分片只终止当前轮次，不使整个页面卡死。

## 8. 后端会话与流水线

### 8.1 VoiceCallSession

每个连接创建一个 `VoiceCallSession`，保存：

- 当前用户和 `session_id`。
- 当前活动 `turn_id` 与取消令牌。
- 输入 PCM 缓冲。
- 当前大模型生成任务、GPT-SoVITS 请求和发送任务。
- 当前记忆快照。
- 轮次耗时指标。

用户新一轮发言开始时，旧轮次立刻失效。任何异步任务在发送文字或音频前都再次检查 `turn_id` 和取消状态。

### 8.2 ASR

前端已提供 16 kHz、单声道、PCM16，因此后端直接构造 SenseVoice 所需输入，不再为每句话启动 FFmpeg。SenseVoice 模型随 UNA 后端启动并保持常驻。

首版在 `user_speech_end` 后执行一次最终识别；不把频繁的中间识别加入关键路径。识别为空或置信度不足时返回可恢复错误并重新进入监听。

### 8.3 大模型

实时语音使用专用系统提示入口，但复用 UNA 的人格、用户上下文和安全规则。提示词明确禁止输出 `ACTION:`、Live2D 参数、Markdown 控制块或舞台指令。

大模型采用流式输出。后端保留首个短句快速封口和后续自然合并，但语音通话路径不复用需要媒体文件与 Rhubarb 的现有 `SpeechReplyDelivery`。文本增量立即发给前端；可朗读单元进入本轮 GPT-SoVITS 流水线。

### 8.4 GPT-SoVITS

实时语音路径直接调用本机 GPT-SoVITS：

- 默认 `streaming_mode=2`，在延迟与音质间取平衡。
- 使用 `media_type=raw`，直接消费响应中的 PCM 字节流。
- 不生成 MP3，不落磁盘，不创建媒体票据，不执行 Rhubarb。
- 每个语音单元保持严格顺序；前一单元开始产出后即可继续准备后续文本，但不能造成声音重叠。
- 保留 `streaming_mode=3` 作为可配置的低延迟实验选项，不作为默认值。

后端必须从 GPT-SoVITS 当前推理配置或输出管线取得实际输出采样率，并在 `tts_start` 中告诉前端，不能把采样率写死在浏览器中。断开连接或插话时主动关闭 HTTP 流；如果底层推理无法立即停止，所有迟到字节仍由 `turn_id` 屏障丢弃。

正常路径只使用克隆音色。GPT-SoVITS 不可用时，本地首版返回明确错误并回到监听；是否启用 Edge TTS 降级由用户后续单独决定，避免在通话中突然变换音色。

## 9. 插话与取消

插话是实时通话的核心规则，不是异常情况：

1. UNA 播放期间，VAD 连续检测到约 200 ms 有效用户语音。
2. 前端立即停止当前 AudioBufferSource、清空旧播放队列并将本地状态切到 `listening`。
3. 前端发送携带旧 `turn_id` 的 `interrupt`，为新发言创建新 `turn_id` 并发送 `user_speech_start`，随后上传新一轮的预留 PCM。
4. 后端标记旧轮次取消，停止继续消费大模型流和 GPT-SoVITS 流。
5. 所有属于旧 `turn_id` 的迟到文本、音频和结束事件在两端均被丢弃。
6. 新语音结束后以已经创建的 `turn_id` 发送 `user_speech_end`，正常进入识别和回复。

前端静音必须先于服务端确认，因此用户听到的停止不依赖网络往返。背景电视或扬声器回声可能误触发插话，首版优先依赖浏览器 AEC，并允许在设置中调整插话灵敏度；不因误触发而关闭该能力。

## 10. 与现有记忆的关系

实时语音与文字聊天必须共享同一用户、同一 UNA 和同一数据库：

- 通话建立时一次性加载轻量 `CallMemorySnapshot`：用户资料、UNA 人设、最近 20 轮对话和有界的相关长期记忆。
- SQLite 中的资料和最近对话同步读取；向量记忆读取默认最多等待 150 ms，超时则使用已有快照开始通话，不阻塞 `call_ready`，该阈值集中配置并保留调优能力。
- 同一通话中复用快照，并把新完成的轮次追加到内存上下文，不为每句话重新执行完整记忆初始化。
- 每个完整轮次立即写入现有私有对话记录，保证切回文字页可以看到。
- 事实抽取、反思、摘要、向量写入和人格演化在轮次结束或通话空闲时异步执行，不阻塞第一声音。
- 被插话取消且没有完成的 UNA 回复不作为完整事实写入长期记忆；用户最终识别文本仍可随新的完整轮次一起保存。

后续完善五层记忆时，只替换 `CallMemorySnapshot` 的提供者，不改变音频协议和通话状态机。因此实现顺序必须是“实时语音主链路先闭环，再深化记忆层”。

## 11. 错误恢复

- 麦克风拒绝：停留在页面并说明如何授权，不反复弹窗。
- VAD/Worklet 加载失败：结束本次通话，不回退到 Live2D 页面内部录音。
- WebSocket 断开：立即停止采集和播放；本地首版允许用户手动重连，不自动重放旧轮次。
- ASR 空结果：提示未听清并恢复监听，不调用大模型和 TTS。
- 大模型失败：当前轮次返回错误并恢复监听。
- GPT-SoVITS 失败：停止当前音频，保留已经显示的文字，恢复监听。
- 浏览器切到后台导致 AudioContext 暂停：返回前台后要求一次用户点击恢复，不偷偷累积并突发播放旧音频。
- 页面卸载或结束通话：关闭麦克风轨道、AudioWorklet、VAD、播放器、WebSocket 和所有后端轮次任务。

## 12. 性能指标与观测

在模型已预热、GPT-SoVITS 无其他排队、本机桌面浏览器的条件下，首版目标为：

- 用户停止说话到第一段可听声音：中位数不超过 1.5 秒，P95 不超过 2.5 秒。
- 前端检测插话到旧声音停止：不超过 150 ms。
- 后端收到中断到旧轮次停止继续发送：不超过 300 ms。
- 播放开始后，相邻 PCM 调度不得出现超过 150 ms 的非语义断粮。
- 连续通话 30 分钟，无重复播放、乱序、旧轮次串音、麦克风轨道泄漏和持续增长的音频队列。

每轮只记录阶段和耗时，不记录 Access Token、WebSocket 票据、完整用户语音或提示词：

- VAD 结束等待。
- PCM 上传与字节数。
- ASR 耗时。
- 记忆快照命中/超时。
- 大模型首字与首个可朗读单元耗时。
- GPT-SoVITS 首字节与每个单元耗时。
- 前端首播等待、缓冲深度、断粮和插话停止耗时。

## 13. 分阶段实现顺序

### P0：解耦与协议骨架

- 建立独立语音通话页面、路由级拆包和专用 WebSocket。
- 建立 `VoiceCallSession`、状态机、`session_id`/`turn_id`、JSON 控制消息和 PCM 二进制帧协议。
- 验证进入语音页时不加载 PixiJS、Live2D 模型和 Rhubarb。

### P1：实时输入与识别

- 接入 AudioWorklet、16 kHz PCM 和本地 Silero VAD。
- 后端绕过 FFmpeg，直接把 PCM 交给常驻 SenseVoice。
- 先完成“说话 → 自动停句 → 显示最终识别文本”的独立闭环。

### P2：流式回复与克隆语音

- 接入流式大模型、专用文本封口和 GPT-SoVITS raw PCM。
- 接入前端 120 ms 小缓冲播放器和严格序号播放。
- 达成第一声音与句间连续性指标。

### P3：插话与恢复

- 完成前端立即静音、后端取消、旧轮次屏障、断线和后台恢复。
- 连续进行快速插话、空识别和服务失败压力测试。

### P4：共享记忆

- 完成 `CallMemorySnapshot`、通话内上下文更新、对话统一落库和异步长期记忆固化。
- 验证文字页与语音页看到同一历史，用户之间数据隔离不变。

### P5：本地稳定性与移动端准备

- 完成 30 分钟桌面通话和资源泄漏验收。
- 再进行局域网手机、移动浏览器/HBuilderX 麦克风权限和音频策略适配。
- 公网阶段另行设计 WebRTC、弱网、安全限流和服务扩容，不在本设计中提前引入。

## 14. 验收标准

1. 打开实时语音页的网络和构建产物中，不请求 Live2D 模型、动作文件、PixiJS 或 Rhubarb 资源。
2. 连续说 20 句均能自动判断停句并返回最终转写，无需重复点击录音按钮。
3. UNA 使用当前 GPT-SoVITS 克隆音色逐步开始说话，而不是等完整 MP3 文件生成。
4. UNA 说话时用户插话，旧声音立即停止，后续不会再出现旧文字、旧音频或旧结束事件。
5. 文字聊天与语音通话共享历史和记忆；切回文字页可看到已完成的通话轮次。
6. 用户 A 无法读取用户 B 的转写、回答或记忆。
7. Live2D 页面发生加载失败或动作异常时，独立语音通话仍可正常使用。
8. 结束通话后，浏览器麦克风指示关闭，前后端均不存在残留活动轮次。
9. 预热条件下满足第 12 节的首声、插话和连续播放指标。

## 15. 已确定的设计边界

- 传输：本地第一版使用 FastAPI WebSocket，不使用 WebRTC。
- 输入：浏览器 AudioWorklet + 本地打包的 `@ricky0123/vad-web`/Silero VAD。
- ASR：现有 SenseVoice 常驻模型，直接接收 16 kHz PCM，绕过逐句 FFmpeg。
- TTS：现有 GPT-SoVITS 克隆音色，默认流式模式 2、raw PCM。
- 播放：AudioContext 小缓冲连续调度，不走 MP3、媒体票据和 Rhubarb。
- 取消：客户端立即停播，服务端按 `turn_id` 取消与隔离。
- 记忆：先快照、后异步固化，与现有私有数据共享；不让深度记忆阻塞首声。
- Live2D：实时语音入口完全不加载、不调用、不等待。
