# Live2D 动作渲染顺序修复设计

## 1. 背景与目标

P1 动作编译、混合和 WebSocket 链路已经完成，但真实浏览器中出现以下现象：

- 用户发送“请慢慢左右摇头两次并眨眼”等明确动作命令后，模型没有可见动作；
- AI 文字、语音和媒体缓存正常；
- 模型自身的自然眨眼仍然存在；
- 自动化测试全部通过，但未复现真实 PIXI/Live2D 渲染顺序。

本次修复的目标是让已经生成并进入状态混合器的用户动作、AI 动作、情绪、呼吸和口型，在 Live2D 原生动作与物理计算完成后、模型绘制前稳定写入，从而真正显示在屏幕上。

本次只修复动作“已生成但不可见”的渲染时序问题，不扩展“哭泣”等新的动作语义，也不修改登录、记忆、语音合成或 WebSocket 协议。

## 2. 根因证据

当前控制器把参数写入函数注册到 `app.ticker`，优先级为 `-25`。PIXI 5.3.3 的应用渲染函数也以 `UPDATE_PRIORITY.LOW`，即 `-25` 注册；同优先级的新监听器排在已有监听器之后。

实际运行顺序为：

1. `Live2DModel.onTickerUpdate()` 只累计 `deltaTime`；
2. PIXI 应用开始渲染；
3. `Live2DModel._render()` 调用 `internalModel.update()`，重算原生 motion、expression、物理、呼吸和自然眨眼；
4. Live2D 立即绘制模型；
5. 当前控制器的 `-25` Ticker 才写入语义动作参数；
6. 下一帧绘制前，这些参数又被 `internalModel.update()` 覆盖。

因此控制器虽然每帧都计算并写入参数，但写入发生在绘制之后，用户看不到任何一帧。模型自身的自然眨眼由步骤 3 生成，所以仍然可见。

## 3. 方案比较

### 方案 A：只调整 Ticker 优先级

把控制器优先级从 `-25` 改为 `-24`，让它在 PIXI 渲染监听器之前执行。

不采用。Live2D 的 `internalModel.update()` 位于 `_render()` 内部，控制器即使先于渲染执行，仍会在真正绘制前被原生更新覆盖。

### 方案 B：关闭 Live2D `autoUpdate`，完全接管更新与绘制

关闭模型自动更新，由 UNA 自己驱动时间、motion、physics、参数覆写和绘制。

不采用。它会复制第三方插件的大量生命周期逻辑，容易破坏纹理、WebGL 上下文、物理、模型切换和移动端兼容，超出本次修复范围。

### 方案 C：在模型原生更新完成后追加 UNA 参数投影

推荐采用。为当前模型实例包装 `internalModel.update()`：

1. 先调用并完整保留第三方插件原始 `update()`；
2. 原始更新返回后，采样 UNA 状态混合器；
3. 把语义通道、呼吸和口型投影到模型参数；
4. 返回给 `_render()`，由原插件立即绘制。

该方案只改变参数写入时机，不复制渲染器，不改变动作协议，也不禁用 Live2D 原生能力。

## 4. 运行时设计

### 4.1 模型就绪

`Live2DViewer` 继续通过 `modelReady` 令牌提供真实模型实例、模型名称和版本。控制器仅在以下条件全部满足时接管：

- `modelReady.modelName` 与当前模型一致；
- `modelReady.model` 与 `modelRef.current` 是同一实例；
- `internalModel.update` 是函数；
- `coreModel.setParameterValueById` 可用；
- 能力表已经由当前真实 `coreModel` 建立。

### 4.2 后更新挂钩

控制器保存当前 `internalModel.update` 的原始函数，并安装实例级包装函数。包装函数必须：

- 使用原始 `this` 和原始参数调用原函数；
- 只有原函数成功返回后才执行 UNA 参数投影；
- 将毫秒级 `deltaTime` 换算为控制器需要的帧步长；
- 保持原始返回值；
- 单个语义参数写入失败时继续处理其他参数；
- UNA 投影异常时只跳过当前帧，下一帧可恢复；
- 不吞掉第三方原始 `update()` 抛出的异常。

### 4.3 每帧参数顺序

每次原生更新后的 UNA 层按以下顺序执行：

1. 更新情绪插值、UNA 眨眼计时和呼吸相位；
2. 根据当前时间采样 `Live2DStateMixer`；
3. 投影普通语义通道；
4. 投影 UNA 呼吸保留层；
5. 最后投影 TTS 口型保留层。

口型仍保持最终写入，动作轨道不得接管嘴部参数。

### 4.4 生命周期与模型切换

控制器为每个真实模型实例最多安装一次挂钩。

在模型切换、模型实例替换或组件卸载时：

- 仅当当前 `update` 仍然是本控制器安装的包装函数时，恢复保存的原始函数；
- 清空旧能力表；
- 重置状态混合器；
- 旧模型的异步结果不得重新接管新模型；
- 新模型就绪后重新建立能力表并安装新的挂钩。

不再使用独立的 `app.ticker` 参数写入回调，也不再轮询等待 Ticker。

## 5. 测试设计

### 5.1 真实顺序回归测试

测试替身必须模拟第三方插件的实际顺序，而不是只手动调用控制器 Ticker：

1. 原生 `internalModel.update()` 先把 `ParamAngleX` 重置为默认值；
2. UNA 已入队一个摇头轨道；
3. 模拟 `_render()` 调用 `internalModel.update()` 后立即读取绘制值；
4. 修复前绘制值为默认值，测试失败；
5. 修复后绘制值必须为非零动作值。

这个测试捕获的生产回归是：“把 UNA 写入重新移到独立 Ticker，导致绘制前被原生更新覆盖”。

### 5.2 生命周期测试

补充验证：

- 原生 `update()` 仍被调用一次，参数和返回值不变；
- 模型切换后旧实例恢复原函数，新实例安装新挂钩；
- 重复的 ready 令牌不会叠加包装；
- 卸载后恢复原函数；
- UNA 当前帧异常不会永久停止后续帧；
- 原生 `update()` 异常仍向上传递。

### 5.3 回归范围

运行：

- `useLive2DController` 定向测试；
- 前端全部 Vitest；
- 后端全部 Pytest；
- Vite 生产构建；
- PowerShell 发布与入口资源哈希检查；
- 浏览器人工检查点头、摇头、眨眼并行、否定句、模型切换、刷新重连、后台恢复和口型。

## 6. 验收标准

- “请轻轻点头两次”有两次可见点头；
- “请慢慢左右摇头两次并眨眼”可见摇头与眨眼并行；
- 普通对话仍有自然微反应；
- 否定句不触发被否定动作；
- 模型切换后新模型可执行动作，旧动作不重播；
- 语音播放期间口型正常；
- 模型自然眨眼和原生物理不被破坏；
- 浏览器控制台没有持续异常；
- 自动化测试和生产构建通过；
- 中文功能清单记录本次修复及验证状态；
- 修复先保留在 `codex/p1-live2d-motion-v3`，未经用户选择不合并 `main`。

## 7. 已知非目标

- “你能哭一下吗”不属于当前即时动作解析器的固定动作集合；
- 真正眼泪效果需要模型具备泪水参数、部件或贴图；
- GPT-SoVITS 未启动时继续降级到 Edge TTS，本次不调整语音服务；
- Android APK 真机验收仍作为独立发布验收项。
