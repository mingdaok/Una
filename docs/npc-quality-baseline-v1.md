# NPC 模拟质量评估与调参基线 v1

## 目标

单个测试世界只能说明某个具体故事是否合理，不能判断模拟系统整体是否过于重复、过于安静或难以形成长期行动。本工具会在临时数据库中批量运行多个确定性种子，给出可重复比较的量化基线。

质量评估只在 `UNA_ENV=development` 时可用。每次运行会创建临时 SQLite 世界，评估结束后整个临时目录自动删除，不会向当前用户数据库写入人物、事件、关系或建议。

## 使用方法

1. 进入“NPC 世界检查”。
2. 切换到“质量评估”。
3. 输入 1–20 个不重复的种子，用逗号、中文逗号或换行分隔。
4. 选择每个种子运行 1–7 天。
5. 点击“开始评估”。

默认使用三个种子、每个种子三天，适合开发中的快速回归。准备调整关系节奏或意图规则时，建议使用 10–20 个种子、每个种子 7 天。

## 隔离评估流程

每个种子会：

1. 从种子对应的确定性世界时间创建所有启用 NPC。
2. 给每个 NPC 提交一个标准化建议，用于覆盖接受、调整、延后和拒绝分支。
3. 推进所选天数，结算独立生活、共同互动、关系和意图。
4. 只提取聚合指标与安全计数。

人物数量来自集中角色配置，不固定假设为三人。以后禁用或新增预设角色时，“事件 / 人物日”分母会自动调整。

## 核心指标

### 事件 / 人物日

`NPC 事件总数 ÷ 所有种子的启用人物数 ÷ 模拟天数`

- 太低：角色长时间没有可观察生活。
- 太高：生活可能像连续日志流水，重要事件被淹没。
- v1 自动提示线：低于 2。

### 摘要重复率

`1 - 独立事件摘要数 ÷ NPC 事件总数`

它衡量文本层面的重复，不代表相同作息一定有问题。固定睡眠和吃饭本来就会重复，应结合事件类型分布判断。

- v1 自动提示线：高于 75%。

### 互动 / 种子日

`共同互动总数 ÷ 种子数 ÷ 模拟天数`

它反映 NPC 关系变化对用户是否足够可见。

- v1 自动提示线：低于 0.15。

### 冲突与修复

- 冲突数：`relationship_friction` 事件数。
- 修复数：`relationship_repair` 事件数。
- 修复/冲突：用于发现冲突长期无法收束或修复过于机械的问题。

短批次没有冲突并不表示规则失效。关系通常需要先累积熟悉、信任或紧张，建议使用七天批次并增加种子数。

### 意图完成率

`已完成意图数 ÷ 已形成意图数`

- 太低：行动延迟、截止时间或已有计划互斥可能过强。
- 太高：人物可能缺少犹豫、调整和失败。
- v1 自动提示线：形成过意图且完成率低于 30%。

### 建议结果分布

统计 `accepted`、`adjusted`、`deferred`、`declined`。评估使用标准化建议，不代表真实用户建议的最终产品分布，但适合比较规则修改前后自主性是否发生突变。

### 关系层级与事件类型

关系层级按方向统计，因此同一对人物可能产生两条关系记录。事件类型展示最高频的八项，用于快速发现某类日程垄断生活的问题。

## 推荐调参流程

1. 使用固定种子集合运行基线并保存数字。
2. 一次只修改一个规则域，例如互动节奏或意图阈值。
3. 使用完全相同的种子和天数重新评估。
4. 比较指标变化，再进入世界检查器查看具体事件是否自然。
5. 同时通过量化基线和具体故事验收后，再保留改动。

推荐种子集合示例：

```text
baseline-01, baseline-02, baseline-03, baseline-04, baseline-05,
baseline-06, baseline-07, baseline-08, baseline-09, baseline-10
```

## 开发接口

`POST /api/life/acceptance/evaluate`

请求示例：

```json
{
  "seeds": ["baseline-01", "baseline-02"],
  "days": 3
}
```

接口要求正常登录，但不会使用或写入登录用户的生活世界。生产环境不会注册该路由。

## 当前边界

- v1 统计的是规则模拟质量，不评价自然语言对话是否好听。
- 摘要重复率按完全相同文本计算，不包含语义相似度。
- 自动提示是调参信号，不是上线门禁。
- 批量评估是同步开发接口，最多 20 个种子 × 7 天，避免无边界计算。
- 朋友圈、日记和主动消息的生成质量需要单独的内容评估阶段。
