# NPC 关系与互动 v1 开发基准

## 目标

共同经历只保存一条客观事件，但每个参与者拥有自己的理解、情绪变化和私密想法。关系变化必须引用共同事件作为证据，不能只改数值而没有事实来源。

## 集中互动模板

互动内容配置在 `characters/presets.yaml` 的 `interaction_templates`：

- `summary_template` 使用 `{actor_a}`、`{actor_b}` 占位符，不绑定当前人物姓名。
- `perspectives.actor_a` 和 `perspectives.actor_b` 分别描述双方理解及私密想法。
- `relationship_delta` 定义熟悉度、好感、信任、紧张和人情变化。
- 重要程度、可提及程度和可公开程度仍由模板集中配置。

业务代码不得根据小满、知夏或阿岚等显示名称选择互动。

## 数据模型

### `ai_interaction_events`

共同事件的唯一客观事实：类型、时间、地点、摘要、来源日程、重要程度和幂等键。

### `ai_interaction_participants`

记录参与者及角色：`initiator` 或 `participant`。同一共同事件至少需要两名参与者。

### `ai_interaction_perspectives`

每位参与者独立保存：

- 信息来源与置信度
- 对事件的理解
- 情绪变化
- 私密想法
- 披露等级

客户端接口只返回当前查询人物的安全解释，不返回任何参与者的 `private_thought`。

## 互动来源

### NPC 与 NPC

- 只在两人的晚间日程均已完成后撮合。
- 每个用户世界采用稳定的三天节奏，约每三天一次，不会每晚机械配对。
- 参与者和模板根据用户、日期和稳定 ID 确定；重复结算结果一致。
- 事件保存双方来源日程 ID。
- 双方各写一条方向相反的关系记录，并共享同一证据事件 ID。

### UNA 与 NPC

既有 UNA `friend_chat` 事件会桥接为共同事件：

- UNA 保留原事件中的第一视角。
- NPC 获得自己的解释和私密想法。
- 原有 UNA → NPC 关系不重复累加。
- 新增 NPC → UNA 的反向关系，使关系成为双向状态。
- 共同事件保存原生活事件 ID，保证来源可追踪。

## API 与聊天

- `GET /api/life/actors/{actor_id}/interactions`：查询人物参与的共同事件和该人物的安全视角。
- `GET /api/life/actors/{actor_id}/relationships`：查询人物自己的关系状态。

用户询问具体 NPC 近况时，共同事件可以进入聊天上下文。上下文会列出全部参与者，并明确当前使用谁的视角，禁止混淆参与者或公开私密想法。

## 后续顺序

1. 用户建议转为 NPC 可接受、延后或拒绝的意向。
2. 关系阈值影响互动概率、内容和冲突修复。
3. 共同事件按公开程度进入朋友圈，但同一事件最多由一名参与者首发。
4. NPC 状态、关系、日程、事件和来源的调试界面。
