# NPC 关系阈值与冲突修复 v1 开发基准

## 目标

关系数值不再只是展示字段，而是直接影响人物选择谁互动、互动可能发生什么，以及 UNA 能从对方那里听到多深的内容。

关系仍是方向性的：A 对 B 与 B 对 A 分别保存。共同互动撮合和冲突判断使用双方指标的平均值，关系 API 则返回查询人物自己的方向。

## 关系接近度与层级

接近度计算：

`熟悉度 × 0.25 + 好感 × 0.35 + 信任 × 0.40 - 紧张 × 0.30`

默认层级集中配置在 `relationship_policy.tiers`：

- `distant`：0；
- `familiar`：15；
- `close`：40；
- `trusted`：65；
- `strained`：紧张达到 45 时覆盖普通层级。

API 增加 `closeness_score`、`relationship_tier` 和 `disclosure_level`，但仍不返回私人关系摘要。

## 互动撮合

候选人物两两组合后，根据接近度、未解决的紧张和稳定扰动计算优先级。关系较近的人更容易自然见面；少量紧张会保留“还有话没说完”的机会，但不会让高冲突关系无限高频碰面。

相同用户、日期和关系状态会得到稳定结果，不依赖随机进程状态。

## 冲突

只有双方平均紧张达到 `conflict_trigger_tension` 时才进入冲突候选，并再经过按用户、人物和日期计算的低频概率门。

冲突是一个普通共同事件：

- 一条客观事实；
- 双方各自独立的理解与私密想法；
- 双向关系分别增加紧张、降低好感和信任；
- 事件 ID 同时成为两边关系变化的证据；
- 低公开度防止它被随意发布到朋友圈或透露给关系疏远的 UNA。

## 修复

如果上一件双方共同事件是冲突，当前紧张仍达到修复阈值，并且平均信任不低于 `repair_min_trust`，下一次合适互动优先选择修复模板。

修复不会清空冲突历史，也不会强制恢复到原状态。它只降低部分紧张并增加有限信任和好感，因此可能需要多次正常互动才能真正回暖。

没有最低信任基础时不自动生成修复事件。

## 披露深度

NPC 对 UNA 的方向性关系会限制聊天上下文中的最低公开程度：

- `distant`：只允许公开度至少 20 的生活和共同事件；
- `familiar`：允许公开度至少 5；
- `close`、`trusted`：可以使用全部非私人记录；
- `strained`：提高到 45，只保留更公开、更安全的内容。

任何 `private` 记录仍然禁止进入聊天上下文。关系层级不能覆盖硬隐私边界。

## v1 边界

- 冲突由既有紧张触发，v1 不从任意聊天文本自动判定冒犯。
- 冲突和修复目前只发生在 NPC 与 NPC 的共同互动中。
- 关系衰减、道歉措辞个性化、长期疏远和彻底断联留待后续阶段。
- 前端调试界面可直接使用关系 API 返回的层级与接近度。
