# QQ 机器人手动测试

按顺序做。通过就在方框打勾；失败记下时间、操作和截图。暂时没有条件测试的，写“未测”。

## 先准备好

- 用专门的机器人 QQ、小号和测试群。
- 在这个工作区操作：`D:\ai\Una\.worktrees\qq-chatbot\Una`。
- 首次安装、配置和启动按 [部署说明](qq-setup.md) 做；测试地址是 `http://127.0.0.1:8001`。
- `.qq.env` 中开启 QQ，填好机器人 QQ、允许私聊的小号、测试群、令牌。模型服务也要启动。
- 协议端登录机器人 QQ，反向 WebSocket 填：`ws://127.0.0.1:8001/integrations/qq/onebot/ws`，令牌与 UNA 一致。
- 在测试网页注册新账号。原项目账号和聊天记录不会自动复制过来。

## 第一轮：先确认能用

| 勾选 | 怎么测 | 什么样算通过 |
|---|---|---|
| [ ] | 打开网页 → 导航菜单 → QQ 连接 | 面板能打开，机器人显示已连接 |
| [ ] | 网页生成绑定码，按提示用小号私聊机器人，再回网页确认 | 显示已绑定；共享选项默认关闭 |
| [ ] | 私聊发“你好，介绍一下自己” | 收到正常文字回复；没有把同一内容重复发两遍 |
| [ ] | 发“我刚才说了什么？” | 能接上本次 QQ 私聊的上下文 |
| [ ] | 发一张清楚的照片，并问“图里有什么？” | 回复与图片内容相符 |
| [ ] | 发一段 5～10 秒的语音：“帮我推荐一道晚饭” | 能理解意思；默认收到文字和可播放的语音 |
| [ ] | 网页面板把语音模式改成只发文字，再发语音 | 能理解，但只回复文字 |
| [ ] | 管理员在面板启用测试群，在群里 @机器人问问题 | 正常回复，不需要给每位群成员绑定账号 |
| [ ] | 引用机器人刚发的群消息追问 | 能回应追问 |
| [ ] | 在群里 @机器人，并明确说“请用语音回复你好” | 有文字和可播放的语音；普通群问题默认只回文字 |

长回复可能正常拆成几条。判断重复时，看是否把同一段内容又发了一遍。

## 第二轮：确认不会乱说、乱读

| 勾选 | 怎么测 | 什么样算通过 |
|---|---|---|
| [ ] | 两个人在测试群正常聊几轮，话题有时与 UNA 有关、有时只是彼此聊天 | UNA 能择机参与，也能保持沉默；不要求每次都插话 |
| [ ] | 保持群里没人说话 5 分钟 | UNA 不会自行找话题 |
| [ ] | 观察自主插话时间，不把 @ 和引用追问算进去 | “自然克制”模式至少间隔 3 分钟，每小时不超过 6 次 |
| [ ] | 私聊告诉她一个独特暗号，例如“我的暗号是紫色西瓜482”；再在群里问你的暗号 | 群里不能读出这个私聊暗号 |
| [ ] | 有两个测试群时，在 A 群说独特暗号，在 B 群问 | B 群不能读出 A 群的暗号 |
| [ ] | 共享全部关闭，在网页说一个新暗号，然后在 QQ 问 | QQ 不能从网页读取该暗号；QQ 新对话也不出现在站内历史 |
| [ ] | 开启近期对话共享，再在网页说一个新的暗号，去 QQ 问 | QQ 能使用共享的近期网页上下文；成功交付的新 QQ 对话可出现在站内历史 |
| [ ] | 再关闭共享，然后只在网页说第三个新暗号，去 QQ 问 | QQ 不能读到第三个暗号 |
| [ ] | 用不在白名单的小号私聊，或在未启用的群 @机器人 | 不提供正常聊天回复 |
| [ ] | 在网页解绑，然后继续私聊 | 不能继续正常聊天，重新绑定后才能恢复 |

关闭共享不会删除之前已经进入聊天上下文的内容，所以每次用**全新的暗号**。画像、长期记忆和私人生活共享也应分别开关检查，不能只测一个开关就全部打勾。

## 第三轮：断线和媒体出错

| 勾选 | 怎么测 | 什么样算通过 |
|---|---|---|
| [ ] | 发问题后暂时断开协议端连接，再恢复连接 | 服务能恢复，不连续重复发同一回复；不确定是否已发送的消息允许不补发 |
| [ ] | 发问题后重启 UNA，再继续聊天 | 重启后能继续使用，不把旧回复连续补发 |
| [ ] | 问一个较长的问题，在生成期间马上解绑或关闭共享 | 旧权限下尚未发送的回复不再发出；已发送的内容不会撤回 |
| [ ] | 确保协议端把 4 张图片作为同一条消息上报，再询问 | 提示最多分析 3 张图片，不崩溃 |
| [ ] | 能准备时，发送超过 10 MB 的单图或超过 60 秒的语音 | 明确提示超限，不崩溃；以 QQ 压缩后实际收到的文件为准 |
| [ ] | 临时停止语音合成服务，再要求语音回复 | 文字仍能收到，不会因语音失败把文字重复发送；若启用了备用语音服务，可能仍有语音 |
| [ ] | 用管理员打开 QQ 面板 | 能查看健康状态和失败/不确定任务；普通用户看不到这些管理信息 |

手工断线不能完整证明去重逻辑。如果协议端没有重复事件重放功能，重复事件去重记为“自动测试覆盖，手工未测”，不要靠重复发送两条相同文字来代替。

## 最后：通知和原功能

通知需要等实际条件满足，今天测不了就标“未测”。不要改电脑时间来催通知。

- [ ] 不订阅时，不收到主动问候、日记提醒和生活通知。
- [ ] 开启主动联系及问候，至少 8 小时不私聊，在白天观察是否有问候。
- [ ] 开启日记/生活通知和私人生活共享，有新日记或可披露的生活事件后，观察对应通知。
- [ ] 北京时间 22:00～08:00 不发送主动通知；所有类型合计每天最多 2 条。
- [ ] 关闭订阅后，不再发送尚未发出的通知；重启后不补发过期问候。
- [ ] 网页文字聊天、日记和实时语音仍能正常使用。

## 失败就这样记录

```text
测试项：例如“语音输入”
时间：9 月 26 日 15:20
我做了什么：发了 8 秒语音，问晚饭吃什么
实际结果：只有文字，没有语音
附件：QQ 截图、QQ 面板状态截图、对应时间的后台报错
```

截图和日志里不要带登录令牌或密码。把记录发回来即可定位问题。
