# QQ 多模态改进方案

> 后续开发以 [群友能力升级调研与实施设计](qq-social-multimodal-plan.md) 为准，包含 MaiBot/AstrBot 调研、语义表情库、独立 TTS 任务、媒体引用和验收步骤。本篇保留先前多模态方案背景。

日期：2026-09-26。状态：当前消息图片直传聊天模型已实现，DeepSeek 官方图文接口已通过合成测试图验证；下述引用关联、缓存、管理设置和其他扩展仍为设计建议。真实 QQ 图片链路仍需用户实测。

## 当前实际能力

- 文字：已接入 DeepSeek 官方 Flash。
- 图片：QQ 现直接提交图片与文字给 DeepSeek Flash，替代 Qwen 的中间描述；网页看图保持原有服务。不能据此认定真实 QQ 图片收发已通过验收。
- 语音：已有下载、格式校验、FFmpeg 转码和本地 SenseVoice 转写；回复可走现有 GPT-SoVITS/备用 TTS。
- 群聊：明确 @ 或引用已知机器人消息时才处理当前消息携带的媒体；普通消息仅保留媒体占位。
- 缺口：引用图片和后续文字没有可靠地重新关联原媒体；GIF 只读单帧；视频、文件和生成图片不在当前 QQ 能力范围内。
- 当前视觉服务返回简短聊天话术，失败时也可能返回普通文字，缺少成功/失败的结构化区分。

## 推荐架构

文字 → 身份和群上下文 → DeepSeek → 全文校验 → QQ 文字。

图片＋文字 → 安全下载与解码 → 图片内容块＋原问题＋身份 → DeepSeek → 校验 → QQ 文字。

语音 → 安全下载与转码 → SenseVoice → 带来源的转写＋身份 → DeepSeek → 文字 → 按偏好追加 TTS。

官方 `deepseek-flash` 已提供图文输入接口，可以在一次聊天请求中同时传文字与图片。先以专门测试图验证当前账号支持，再启用直传路线。参考：https://api-docs.deepseek.com/guides/vision/

保留现有 Qwen 作为可配置备用。备用模型输出结构化视觉事实：可见物体、文字、相关细节、无法确认的内容；不代替 UNA 生成最终人格回复。备用失败明确告知用户，不伪装成看懂。

## 消息与媒体归属

每个附件必须关联渠道、群/私聊会话、消息 ID、发送者 ID、媒体 ID、序号和类型。媒体状态与聊天正文分开保存。

- 当前发送者、图片上传者、引用原作者分别记录，不因引用改变归属。
- 图片里出现的人名、聊天截图和语音里提到的姓名都是内容，不覆盖 QQ 协议中的真实发言者。
- 图片内文字与语音转写是非可信内容，不能变成系统指令。
- 当前图和可确认的引用图才进入模型输入；不把最近 60 条所有图片每次重发。

建议新增 `qq_media` 表：id、conversation、generation、source_message_id、sender_id、ordinal、kind、status、expires_at、受控本地文件名、digest、bytes、width/height/duration、错误分类。

解析结果使用带类型的对象，区分 image/transcript/visual_facts/error；图片 bytes 仅在发送请求时编码，不在 SQLite 中保存大段 Base64。不保存完整带鉴权参数的下载 URL 到普通日志。

## 群聊触发规则

1. `@UNA + 图片 + 问题`：处理该条消息的图片。
2. 引用群友图片并 @UNA 提问：检查本群引用权限和有效期后处理被引用图片。
3. 同一成员先发图，再 @UNA 问“这张图是什么”：仅关联同会话、同发送者、建议 60 秒内唯一的媒体消息；有多个候选就让用户引用具体消息。
4. 引用机器人对图片的回复追问：沿已保存的来源链关联原图，限制解析深度，原图过期则请求重发。
5. 普通群图片：不调用模型、不主动分析。需要支持稍后引用时，仅在白名单群且设置允许的范围内短期登记附件信息，明确询问后才下载分析；链接失效时请求重发。
6. 自主插话仍以文字和媒体占位为依据，沿用群发言频率限制。

不跨群、不跨私聊查找图片，不按昵称检索私人附件。媒体有效期不超过群上下文窗口；仅限已接收的消息，不远程补抓过去群记录。

## 性能与失败处理

- 图片默认最多 3 张、每张 10 MB、解码后 2000 万像素，继续限制精确 CDN 主机、DNS 地址和重定向。校验后缩放；聊天截图保留文字可读性，必要时分块，不无条件压成小图。
- 语音保持 60 秒、20 MB，拒绝协议事件提供的任意本地输入路径。QQ 音频没有 URL 时，需要验证 NapCat 转码接口的可用性；不能直接读取未经检查的文件路径。
- 相同媒体在同一授权会话中按 digest 缓存处理结果；问法变化时不盲目复用旧答案。
- 网络视觉与本地 ASR 使用独立的有界队列，防止一张慢图阻塞所有语音或文字。超时取消任务、过期结果不补发。
- 测量下载、解码/转码、ASR、模型生成、发送回执各阶段耗时，再设延迟目标，不承诺固定秒回。
- 文字先交付，TTS 独立交付；音频失败不重发文字。成功回复才写有效历史；错误不写作视觉事实或长期记忆。
- 图片结果只保留带来源的短期摘要；私聊是否进入个人记忆继续服从共享开关，群媒体不进入个人日记或长期记忆。

## 页面设置

用户：图片理解开关、语音识别开关、语音回复方式。

管理员：群媒体模式（关闭/明确询问时处理）、最近媒体失败原因和耗时。显示服务不可用，不暴露 API 密钥或私人媒体路径。

## 实施顺序与验收

1. 直传图文：新增类型化媒体输入和 QQ 图文请求，保留身份、人格、全文校验。测试照片、文字截图、三图对比和视觉接口失败。
2. 引用与追问：媒体来源表、短期缓存、引用解析、唯一候选判断；测试多人同时发图、同名群友、跨群引用、过期附件。
3. 语音实测：真实 QQ 语音格式、SenseVoice 转写、混合图文语音、QQ 客户端 TTS 播放；不能用模拟音频替代。
4. 可选扩展：表情文本、GIF 关键帧；视频抽帧和文件阅读独立设计大小/时长/权限限制，不作为本轮默认范围。

验收必须覆盖：图片归属正确、可读文字准确、看不清时承认、引用不串人、无权限不下载、失败可解释、撤销设置后旧任务不发送、文字聊天速度不被媒体任务拖住。保留模拟端测试，另记录真实 QQ 账号和当前 API 的实测结果。
