| 二：目标、承诺和计划变更 | 已完成 | 持久目标、承诺、锚点/弹性计划、失败/中断/取消、计划差异和建议转目标 |

## 3. 重要决策 LLM 配置

该能力默认关闭。普通行为、硬承诺和离线批量补算不调用模型。

| 环境变量 | 默认值 | 说明 |
|---|---|---|
| `UNA_NPC_DECISION_LLM_ENABLED` | `false` | 仅设为 `1`、`true`、`yes` 或 `on` 时尝试启用 |
| `UNA_NPC_DECISION_LLM_API_KEY` | 空 | 模型密钥；未配置时保持规则决策 |
| `UNA_NPC_DECISION_LLM_BASE_URL` | 空 | OpenAI 兼容服务地址；空值使用 SDK 默认地址 |
| `UNA_NPC_DECISION_LLM_MODEL` | `gpt-4.1-mini` | 重要决策模型名 |
| `UNA_NPC_DECISION_LLM_TIMEOUT_SECONDS` | `8` | 单次调用超时秒数 |
| `UNA_NPC_DECISION_LLM_DAILY_BUDGET` | `3` | 每个 NPC 每日调用上限，代码限制为 0–12 |
| `UNA_NPC_DECISION_LLM_SCORE_GAP` | `8` | 相邻重要候选的最大触发分差，代码限制为 1–30 |

密钥不得写入 YAML、数据库事件、日志、前端或本文档。模型只返回建议，最终选择仍必须来自规则系统已经过滤的候选白名单。


`npm.cmd run build` 会先将锁定版本的 VAD 模型、worklet 和 ONNX Runtime 资源同步到被 Git 忽略的 `frontend_react/public/vad/`。若提示缺少 `@ricky0123/vad-web` 或 `silero_vad_v5.onnx`，先按锁文件恢复依赖，不要将 `node_modules` 或生成的 VAD 资源提交到仓库。

本轮额外完成：

- 恢复类行动不再被通用低状态规则或随机失败打断。
- 失败/中断只按 20%/45% 结算行动收益，并记录审计比例。
- 挑战行动失败率限制为 2%–8%，近期已有挫折时启用冷却。
- 失败与中断使用行动相关说明，移除重复的通用尾句。
- 弹性时段选择记录为 `flexible_choice`，不再伪装成计划取消或临时改主意。
- 生成摘要使用中文地点名；检查页显示后端提供的真实行动来源和地点名。
- 30 天测试新增恢复事件全完成、每百条非完成不超过 15 条和弹性选择不取消计划的门槛。

人工验收时必须重建测试场景；已经持久化的旧事件遵守历史不可变原则，不会被本轮代码回写。

## 5. 安全与兼容边界

- `npc_preset_1`、`npc_preset_2`、`npc_preset_3` 为稳定 ID，业务逻辑不得按显示名称分支。
- `backend/life_simulation/characters/presets.yaml` 仍是人物、行动原子、日程素材和地点配置的权威来源。
- 已持久化的 v1 日程继续按原 `plan_json` 和版本结算，不重写历史。
- 状态、计划、目标进度、事件和决策审计在同一事务内提交。
- 公开 API 不返回 `private_thought`、`private_reason`、完整候选评分或密钥。
- 接受后的硬承诺优先于 Softmax 和重要决策 LLM，不允许普通候选随机覆盖。
- 关闭或未正确配置 LLM 时，系统保持完整的规则决策路径。

## 6. 七项长期增量完成范围

五阶段收口后确认的七项任务已经全部完成：

1. `ai_actor_reflections`、日/周反思、记忆合并、语义/关系记忆整理、显著度检索排序，以及长期记忆和关系衰减。
2. 目标的候选、激活、暂停、放弃、失败、完成、复查和恢复生命周期；所有状态变更写入独立审计表。
3. 资源、人设禁止项、参与者可用性/意愿、不可中断状态、地点、天气、通勤时间和重大剧情许可等硬约束。
4. 邀请、持续关系冲突、目标生命周期改变、重要用户建议和结果接近的重要候选等显式 LLM 触发；最终选择仍受候选白名单约束。
5. 重要决策预算采用数据库原子预占与完成结算，并通过并发测试，防止多个线程或进程同时越过每日上限。
6. 90 天稳定性、停机 14 天补算、配置升级兼容矩阵均已自动化；长期补算保持幂等和默认零 LLM 调用。
7. 检查页支持 30/90 天持久后台质量任务，展示进度与结果并允许取消；同步接口限制在 7 天以内，任务与结果按账号隔离。

检查页同时新增去隐私化的反思和目标状态变更面板。公开 API 不返回反思内部元数据、记忆正文、关系私密摘要、目标私有原因或质量任务的账号主键。

v2 设计正文已经同步更新为当前完成状态，并新增人工验收操作手册和后续增强边界。自动化收口已经完成，但人工验收尚待执行；在人工验收记录全部通过前，不应把当前交付标记为正式体验验收通过。后续开发仍须在每次开始前完整阅读 v2 设计和 v1 基线，并优先保持事实一致、可审计、可回退和用户世界隔离。
