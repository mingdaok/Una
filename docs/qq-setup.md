# UNA QQ 功能：运行与验收

## 已实现范围

普通 QQ / OneBot v11 反向 WebSocket；白名单私聊及网页二次确认绑定；可选共享画像、长期记忆、网页历史与生活事实；群内共享上下文和自主参与；图片、语音识别与可选语音回复；订阅问候、日记提醒和真实生活事件通知；网页用户与管理员面板；持久化接收/发送、失败诊断与重启恢复。

功能默认关闭。真实账号登录、协议端媒体格式兼容性和模型服务可用性必须单独联调。模拟协议测试不代表已经连接真实 QQ。

## 1. 准备独立环境

在 `codex/qq-chatbot` 工作区运行，勿在原项目目录启动本脚本。启动脚本固定使用本工作区 `.qq-data/` 下的新数据库、Chroma 和媒体目录；首次运行需要注册新的测试账号，不会自动导入原项目的用户和历史。

推荐使用已具备项目模型依赖的 Python 环境，明确传入可执行文件路径，避免 PowerShell 普通环境和提升权限环境解析到不同的 Python。项目完整依赖见 `backend/requirements.txt`。图片需要 Pillow，语音需要 FFmpeg、ffprobe、SenseVoice，语音合成需要现有 GPT-SoVITS 配置或启用的 Edge-TTS 降级。QQ 文字不会触发 TTS，但主应用目前仍按原有方式初始化模型服务。

前端按已有锁文件安装并构建：

```powershell
cd frontend_react
npm ci
npm run build
cd ..
.\scripts\publish_frontend.ps1
Copy-Item .qq.env.example .qq.env
```

`npm ci` 会重建当前工作区的 node_modules，运行前确认没有需要保留的依赖目录修改。部署不需要开发测试时使用的 `.qq-deps/`。

## 2. 配置和首次绑定

编辑 `.qq.env`：

- `UNA_QQ_ENABLED=true`。
- `UNA_QQ_BOT_ID`：机器人普通 QQ 号。
- `UNA_QQ_ONEBOT_TOKEN`：至少 32 字符的独立随机令牌，与协议端设置一致。
- `UNA_QQ_ALLOWED_USERS`：允许私聊的 QQ 号，逗号分隔，空值拒绝所有私聊。
- `UNA_QQ_ALLOWED_GROUPS`：允许启用的群号，逗号分隔；群默认关闭，随后由管理员在页面启用。
- `UNA_JWT_SECRET`：本测试运行实例独立的随机密钥，至少 32 字符。
- `UNA_QQ_ADMIN_IDS`：站内账号 ID，不是 QQ 号或用户名。可在登录后通过 `/api/auth/me` 获取。配置后需重启。

不要把真实令牌提交到仓库。`.qq.env` 和 `.qq-data/` 已被忽略。

```powershell
.\scripts\start-qq.ps1 -Python '你的 Python 可执行文件绝对路径' -Port 8001
```

打开 `http://127.0.0.1:8001`，注册测试账号。导航抽屉 → **QQ 连接** → 生成绑定码 → 私聊机器人发送显示的命令 → 回网页确认脱敏 QQ 身份。绑定码 5 分钟有效且只能消费一次。三个基础共享选项及私人生活共享均默认关闭。

仅开启近期对话共享后，QQ 私聊的已成功交付对话才会显示在绑定账号的站内历史中；允许导入网页历史时，会排除已从 QQ 导出的消息，避免上下文重复。群聊完全不进入私人历史或日记。

### 协议端设置

候选 NapCat 独立安装和运行，不由 UNA 安装、修改或重分发。先核对所用版本 [许可证](https://github.com/NapNeko/NapCatQQ/blob/main/LICENSE) 及 [配置文档](https://napneko.github.io/config/basic)。

配置通用反向 WebSocket：

```text
ws://127.0.0.1:8001/integrations/qq/onebot/ws
```

使用专用访问令牌，上报结构化消息数组，握手包含 `Authorization: Bearer <token>` 和 `X-Self-ID: <bot QQ>`。心跳间隔建议 30 秒。UNA 接收 90 秒没有数据的连接会失效；协议端负责重连。不要配置重复的事件上报连接。

扫码登录由账号本人完成。先测试一个白名单私聊和一个专用测试群，不要直接向实际群批量发送测试消息。

## 3. 群聊行为

管理员在 QQ 面板中启用部署白名单内的群。默认“自然克制”：自主发言至少间隔 180 秒，每小时最多 6 次；“安静”为 600 秒、每小时最多 3 次。被 @ 或引用本机器人的已知群消息时优先回应，仍受总并发和用户限流。

普通群消息合并观察 3 秒，并判断是否有必要接话。最近 60 条、最长 24 小时的群历史保留发送者标识；其余成员的普通聊天也会进入这个有限上下文。群里没有新消息时不主动开话题。新话题到达后丢弃已过时的自主回复。

群内图片不要求 @：普通消息先进行参与判断，决定回复后再下载所选目标的相关图片；未参与时只保留媒体占位信息（独立开启的表情收集不受此规则影响）。群内语音输入仍在直接询问时分析。群成员无需绑定站内账号，但群聊任何路径都不能读取个人记忆、私人日记或某个账号的生活世界。

机器人发言默认不引用、不自动 @，即使被 @ 也可直接回答。回复计划 `reply_style` 默认 `plain`，只有需要区分旧消息或交错话题时模型可选 `quote`；长回复只在第一段加引用，纯表情同样遵守该选择。内部回应目标继续保存，因此取消可见引用不影响人物归属和撤回检查。已排队的消息保持原发送内容，新生成的回复使用新规则；本次后端更新需重启生效。

## 4. 媒体与通知

- 图片：每条最多 3 张，每张最多 10 MB、2000 万像素。PNG/JPEG/WebP/GIF 会解码为单帧图片输入视觉服务。
- QQ 图片现在直接作为图文内容块发送给独立聊天模型，不再先经 Qwen 生成描述。本机已使用 DeepSeek 官方 `deepseek-flash` 对合成测试图验证接口；实际 QQ 图片下载仍需实测。图片会校正方向、最长边缩至 2048 像素；Base64 仅在请求内存中存在，不写入对话或长期记忆。网页看图服务保持原配置。
- 测试方法：私聊把图片和问题一起发送；群聊可以不 @ 发图、引用图片提问，或先发图再问“这是什么”。@ 仍优先处理，自主回复仍受群开关、观察窗口和配额限制，并非每张图必回。
- 图片关联顺序：当前消息自带媒体 → 明确引用（最多追溯 4 条引用链）→ 同一发送者最近 120 秒的图片。该发送者最近一次提问已引用图片时，“说话”可接续那条引用；已经转移话题则不重新附带旧图。多个候选时询问具体哪张，不自动取其他人的图；明确引用找不到时也不退回无关图片。正常模式与 95% 测试模式共用此逻辑。
- 规划器可用 `needs_media` 请求查看目标相关图片，但不能提供任意 URL 或跨群选图。下载始终使用数据库内该群、当前会话代次的有效消息元数据。图片来源加入发送依赖，生成后撤回图片会阻止旧回复提交。图片仅随本次模型请求传递，不持久化 Base64。
- 开关代理/TUN 的兼容：`UNA_QQ_MEDIA_DNS_FALLBACK` 默认 `true`，无需修改现有 `.qq.env`。下载先使用系统 DNS；遇到常见 Fake-IP（`198.18.0.0/15`、`fdfe:dcba:9876::/48`）、解析失败或空结果时，使用 HTTPS DNS 获取真实公网地址。先尝试阿里公共 DNS 的两个入口，再尝试 Cloudflare。DNS 服务使用固定启动地址，并验证原域名的 HTTPS 证书，避免再次被系统 Fake-IP 解析影响。
- HTTPS DNS 仅查询允许的媒体域名，不发送图片 URL、签名参数、图片内容或用户消息。返回地址按公网规则校验，下载连接直接使用校验后的地址；每次重定向仍重新检查域名。内网、回环、链路本地地址不会因启用回退而放行。
- DNS 缓存最多 30 秒且不超过应答 TTL；连接失败时清缓存并最多重试一次，改用 HTTPS DNS。下载、解析、重定向及重试共用 30 秒总期限；取消会清理解析任务。功能覆盖聊天媒体下载及表情自动收集，开关梯子无需重启；首次安装本次后端更新需要重启 QQ 服务。
- 若返回“媒体 HTTPS 证书校验失败”，这是证书链或域名问题，不会关闭证书校验来绕过。2026-09-27 只读网络检查发现 `multimedia.nt.qq.com` 的证书域名不匹配；`.com.cn`、`gchat.qpic.cn`、`c2cpicdw.qpic.cn` 在 Fake-IP 环境下可通过 HTTPS 连接。目录根路径返回 HTTP 400 仅证明连接建立，不能代表具体图片或模型识图已经验收。
- 语音：每条 1 段、最多 20 MB / 60 秒，FFmpeg 与 ffprobe 的处理有超时限制。
- 媒体入站必须提供 HTTPS URL。默认允许 `multimedia.nt.qq.com`、`multimedia.nt.qq.com.cn`、`gchat.qpic.cn`、`c2cpicdw.qpic.cn`；协议端返回其他真实 QQ CDN 时，在核实后将**精确主机名**加入 `UNA_QQ_MEDIA_HOSTS`。不支持任意本地输入路径、不跟随到内网、不读取消息提供的 `file://`。
- 私聊默认跟随输入；群内仅明确要求“语音回复”时发送语音。文字先发，音频单独生成和交付；音频失败保留文字，不重发文字。输出是同机协议端可读取的私有目录文件 URI，格式兼容性仍需真实协议端验证。
- 私人音频放在 `.qq-data/media`，不通过静态网站暴露。临时媒体按 24 小时保留期清理。
- 主动通知需用户订阅。北京时间 22:00–08:00 不发送，每天最多 2 条；问候要求至少 8 小时未私聊。日记与生活通知要求开启私人生活共享。生活通知只选经过现有事实校验的近期已完成 UNA 事件。
- 关闭订阅或共享、解绑、账号停用将撤销旧权限任务。关闭共享不会抹去之前已形成的聊天记录或长期记忆。

## 5. 恢复、配额和诊断

SQLite 以 `qq_schema` 记录渠道 schema 版本，首次运行创建 `qq_*` 表。旧 `chat_history` 增加可空来源列。所有群数据留在渠道表；私人历史仅在全文发送成功后导出。运行前备份已有数据库；本工作区启动脚本默认使用新库。

- 全局生成并发默认 2，全局排队 100、单会话排队 5，直接交互默认单用户每分钟 6 次。
- 接收消息具有持久化去重键。进程中断后恢复已持久化任务；OneBot 上游未送达的消息不保证能够找回。
- 回执成功才标记 delivered；发送后回执丢失或进程退出时标记 unknown，默认不重发。管理员页面显示异常，不提供有重复风险的一键重发。
- 发送前尚未建立连接可重试，平台明确拒绝则失败。多段消息的前段失败或不确定时取消后续段和音频。
- 长期记忆使用稳定 turn ID；画像任务采用至多一次恢复策略，崩溃中的画像任务标记 unknown，不自动重复调用模型。
- 同一数据库的 QQ 运行实例持有操作系统文件锁，只允许一个 worker。不要用多个 worker 或自动热重载启动真实机器人。
- 管理员可查看连接心跳、队列统计和最近发送异常；普通用户只能看自己的绑定与偏好。页面不返回密钥、原始群消息或其他用户资料。

回滚：将 `.qq.env` 中 `UNA_QQ_ENABLED=false`，停止协议端连接，重启 UNA。保留渠道数据供诊断，不自动删除历史。

真实验收仍需逐项记录：协议端版本及许可、QQ 客户端版本、登录和心跳、私聊绑定、文字与图片输入、语音识别、语音播放、群主动参与与保持沉默、断线恢复、通知订阅和解绑撤销。不存在真实账号与模型服务证据时，不应宣称这些联调项已通过。

## QQ 独立聊天风格

修改 `backend/prompts/qq-persona.md` 可以调整 QQ 私聊和群聊的语气；每次回复重新读取，改这份文件无需重启。默认短句、有主见、可接梗和适度吐槽，不继承网页心理支持口吻和动作示例。网页风格不变。

QQ 默认要求 15～60 字，复杂问题可展开，生成上限 768 tokens。仍需完整生成并校验后发送；此上限不等于固定响应时长。自主群聊额外有 3 秒合并窗口和发言判断；私聊及被直接询问不经过自主发言判断。首次应用代码改动需要重启 UNA。

## QQ 独立模型接口

在 `.qq.env` 配置 `UNA_QQ_LLM_BASE_URL`、`UNA_QQ_LLM_MODEL`、`UNA_QQ_LLM_API_KEY` 后重启，QQ 文字回复、图片理解、表情描述、群发言判断及 QQ 画像任务使用独立模型。留空模型名时沿用网页模型。网页聊天及网页看图服务、ASR、TTS 不受此设置影响。DeepSeek 官方地址使用非思考模式。密钥只放本地环境文件，不提交。

## 群成员身份与引用

群消息使用“群号＋QQ 号”作为稳定身份，人数、相同昵称、改名和发言顺序不影响代码侧的身份区分。当前发言者、@ 对象和被引用消息的原作者分别传给模型；昵称只用于称呼，原样作为不可信数据处理。机器人自己的回复有独立的 assistant 角色。

数据库 schema v2 自动增加消息身份元数据，旧消息保留原来的 QQ 号，缺少的昵称与引用不猜测补齐。引用只从本群最近 60 条、24 小时以内的已交付记录解析；不存在、已过期或重置前的引用标为 unknown，不远程拉取历史。不会建立群成员的私人画像或导入私聊。

验证身份时让三个以上成员使用相同昵称轮流发不同内容，再互相引用、改昵称追问。代码测试覆盖 1000 个同名成员，但模型的自然语言判断仍可能出错；不明确的“他”需要追问，不能承诺模型永不混淆。
