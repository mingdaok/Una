# NPC 统一模拟验收工具 v1

## 用途

验收工具用于稳定复现 NPC 自主生活、关系互动、意图形成和用户建议结果。它通过当前用户独享的虚拟时钟运行，不修改操作系统时间，也不会影响其他用户。

这些能力只在后端 `UNA_ENV=development` 时注册。生产环境没有对应路由，前端收到 404 后会自动隐藏整个验收控制区。

## 使用入口

1. 打开 UNA 的生活页。
2. 点击顶部“打开 NPC 世界检查”。
3. 在人物信息下方找到“验收时钟”。

## 建立可复现场景

填写场景种子并选择初始场景：

- `刚初始化`：只创建人物初始档案、状态和日程。
- `已生活一天`：从确定性起点推进 24 小时。
- `已生活三天`：从确定性起点推进 72 小时。
- `已生活一周`：从确定性起点推进 168 小时。

第一次点击“建立测试场景”只会展示警告；第二次点击“确认清空当前生活模拟数据”才会执行。相同用户使用相同种子和场景，会得到相同的起点、事件时间、人物行动和关系演进结果。

## 推进模拟时间

场景启动后可点击：

- `+6h`：检查一个或两个生活时间窗的变化。
- `+24h`：检查完整日程、意图和一次日级结算。
- `+72h`：观察多日生活连续性、关系互动和建议重评估。

每次推进成功后，人物列表和当前人物详情会自动重新读取。单次后端调用最多推进 168 小时，避免一次请求产生无边界历史。

“退出虚拟时间”只解除当前用户的虚拟时钟，不删除现有模拟结果。退出后，下一次正常结算会重新使用现实时间。

## 重置范围

重置只删除当前登录用户的生活模拟数据，包括：

- UNA 与 NPC 的生活状态、日程和事件
- NPC 共同互动及安全视角
- 模拟关系、故事线、意图和建议
- 生活主动分享的投递诊断数据

不会删除：

- 用户账号与认证信息
- 普通聊天记录和长期记忆系统数据
- 其他用户的数据
- 集中角色预设 YAML

动态或日记已经是用户可见内容，v1 不会随测试世界重置自动删除；手动验收时应使用专门的开发账号。

## 推荐验收流程

### 确定性重放

1. 使用种子 `review-01` 建立“已生活三天”场景。
2. 记录小满的前五条事件、知夏当前状态、阿岚的关系层级。
3. 使用完全相同的种子和场景再次重置。
4. 确认事件摘要、时间和状态一致。

### NPC 独立生活

1. 建立“刚初始化”场景。
2. 分别记录三个人物的初始状态和未来日程。
3. 推进 24 小时。
4. 确认三个人物产生各自事件，状态变化与活动含义一致。

### 关系冲突与修复

1. 建立“已生活一周”场景。
2. 在“事件与互动”中寻找共同互动。
3. 在“关系网络”中记录双方紧张、信任与关系层级。
4. 继续按 72 小时推进，观察冲突后的修复事件和指标回落。
5. 若当前种子没有触发目标分支，更换种子，不要直接修改数据库。

### 意图与建议

1. 建立“已生活三天”场景。
2. 查看每个 NPC 的活跃意图。
3. 通过既有建议入口提交建议。
4. 推进 24 或 72 小时。
5. 确认建议可能被接受、调整、延后或拒绝，并且只有人物自己形成的意图才会成为行动。

## 开发接口

- `GET /api/life/acceptance/status`
- `POST /api/life/acceptance/reset`
- `POST /api/life/acceptance/advance`
- `POST /api/life/acceptance/release`

所有接口仍要求正常登录，并始终从认证信息中获取 `owner_user_id`。客户端不能指定或重置其他用户。

## 当前边界

- 种子通过稳定映射生成虚拟世界起点；现有模拟器随后继续使用确定性时间窗哈希。
- v1 不提供任意数据库字段编辑或强制指定下一事件。
- v1 不保证每个种子必定触发冲突、修复或某一种建议结果，应通过更换种子覆盖概率分支。
- 虚拟时钟主要用于检查器和生活服务。开发时不应同时运行依赖现实时间的长时间后台验收任务。
