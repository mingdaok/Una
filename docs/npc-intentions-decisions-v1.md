# NPC 意图与自主决策 v1 开发基准

## 目标

NPC 不再只被动执行固定日程。系统会根据人物当下状态、性格、关系和近期经历形成一个短期打算，在至少经过一个时间间隔后，将它兑现成可追溯的计划外生活事件。

v1 采用规则评分而不是自由模型调用，确保离线补算可重放、并发幂等、成本稳定，并且可以解释“为什么这个人物做了这件事”。

## 决策流程

1. 完成到期的固定日程与共同互动。
2. 检查人物是否已有一个活跃意图。
3. 活跃意图到达 `earliest_at` 后，原子生成结果事件并标记完成。
4. 没有活跃意图时，从集中配置生成候选。
5. 根据需求信号、性格权重、关系强度、近期经历、重复惩罚和稳定扰动评分。
6. 保存最高分候选；同一人物同时最多存在一个活跃意图。

意图形成与行动兑现分属不同时间点，聊天中必须区分“打算做”和“已经做”。

## 集中配置

配置位于 `backend/life_simulation/characters/presets.yaml` 的 `intention_templates`。

- `state_metric`、`state_direction`、`threshold`：状态触发条件。
- `base_score`、`need_weight`：基础分和需求信号权重。
- `personality_key`、`personality_weight`：人物性格对选择的影响。
- `target_mode`：`none` 或 `relationship`；只有后者可以选择联系人。
- `summary_template`、`motivation_template`：意图的可见摘要与内部动因。
- `action`：兑现后的事件类型、地点、文案、公开程度、状态和关系变化。

模板文案仅支持 `{actor}`、`{interest}`、`{target}`。三个预设人物的当前姓名和兴趣不硬编码在业务逻辑中，因此最终提交前仍可替换。

## 持久数据

### `ai_actor_intentions`

保存：

- 意图实例、模板和驱动力；
- 活跃或完成状态；
- 安全摘要与内部动因；
- 可选目标人物；
- 最终分数、候选分数和评分证据；
- 来源状态版本、形成时间、最早执行时间和截止时间；
- 结果生活事件 ID；
- 每用户、人物、日期和规则版本组成的幂等键。

内部评分、内部动因和完整行动参数不会由客户端 API 返回。

### `ai_actor_states.active_goals`

活跃意图会同步成简化目标。意图完成后目标被移除，状态变化与意图结果事件在同一数据库事务中写入。

### `ai_actor_events`

兑现事件使用 `facts.source_kind = npc_intention`，并保留意图实例、模板、驱动力和模拟器版本。事件没有固定日程 ID，以明确表示它属于自主的计划外行动。

## 状态、关系与表达

- 行动可改变精力、饥饿、压力、社交需求和独处需求。
- 只有 `target_mode: relationship` 的行动可以留下关系证据和关系增量。
- 可公开程度达到朋友圈阈值的结果事件，可以被现有表达层发布；同一事件仍使用来源幂等键避免重复发布。
- 用户询问具体 NPC 时，活跃意图可以进入聊天上下文，但会明确标注为尚未完成的打算。

## API

- `GET /api/life/actors/{actor_id}/life`：增加安全意图列表。
- `GET /api/life/actors/{actor_id}/intentions`：按 `active` 或 `completed` 查询意图历史。

API 不返回 `score`、`decision_context`、`motivation` 或完整 `action`，避免把内部人格推断和决策过程直接暴露给客户端。

## v1 边界

- 每位 NPC 同时最多一个短期意图。
- 意图形成后至少等待六小时才兑现，避免同一次结算里“刚想就完成”。
- v1 的截止时间用于审计；超期后仍会在下次结算补做，而不是静默丢失。
- 自主联系当前记录为发起人物的独立生活事件和单向关系变化；需要双方视角的线下共同经历仍由互动系统负责。
- 用户建议转化为 NPC 可接受、延后或拒绝的意图，留到下一阶段。
